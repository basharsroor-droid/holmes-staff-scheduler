# מדריך הרצת פיילוט — ShiftPilot

מבוסס על `09_First_Pilot_Execution_Plan_AR.docx` (מסלול P1-09). זה שונה מ"הפיילוט מול הולמס פלייס" שכבר מוזכר ב[מפת הדרך](https://claude.ai/code/artifact/9a06ea37-4836-45e8-870a-dfbab53bfdc3) — זו לא הזמנת עובדים בפועל, זו המתודולוגיה: איך בוחרים, מסכמים, מודדים ומחליטים, כדי שהפיילוט הבא (הולמס פלייס או אחר) לא ירוץ על תחושת בטן.

## 1. Scorecard לבחירת מועמד — 5 נקודות

לפני שבוחרים איפה להריץ פיילוט, לנקד כל מועמד (1–5 לכל נקודה):

| קריטריון | שאלה | ניקוד |
|---|---|---|
| **כאב אמיתי** | יש להם היום בעיה קונקרטית בסידור (לא "יכול להיות נחמד")? | |
| **סניף אחד, גודל סביר** | 3–15 עובדים בסניף אחד — מספיק כדי ללמוד, קטן מספיק כדי לתקן מהר? | |
| **בעל תפקיד מחויב (Sponsor)** | יש אדם אחד שאחראי על ההצלחה מהצד שלהם, לא "כולם קצת"? | |
| **מוכנות** | פתוחים לשנות תהליך עבודה קיים, לא רק "לנסות בלי לשנות כלום"? | |
| **מסלול המשך ריאלי** | אם הפיילוט מצליח, יש סיכוי אמיתי שיהפוך ללקוח משלם — לא רק חבר שעושה טובה? | |

**כלל:** לבחור **אחד** בלבד, לא כמה מקבילים — הסיכון המרכזי בתוכנית עצמה הוא "פיילוט רחב מדי", והבקרה היא סניף אחד ומחזור אחד.

## 2. Pilot Charter — תבנית

```
פיילוט ShiftPilot — [שם העסק]

תקופה: [2–4 שבועות, תאריך התחלה וסיום קונקרטיים — לא "בערך חודש"]
היקף: סניף אחד — [שם הסניף], [מספר] עובדים
Sponsor מטעם העסק: [שם + תפקיד]
מה כן כלול: הגשת זמינות, בניית סידור, פרסום, בקשות החלפה
מה לא כלול: [למשל: אינטגרציה עם מערכת שכר קיימת, כמה סניפים]

תנאים:
- ללא עלות בתקופת הפיילוט
- הנתונים שיוזנו הם נתוני אמת (לא נתוני בדיקה) — ראו הערת פרטיות למטה
- בסוף התקופה: החלטה משותפת על המשך/עצירה/מעבר ללקוח משלם

הערת פרטיות: עד שיש DPA חתום (מסלול 05, טרם קיים) אין להזין
מספרי תעודת זהות מלאים או מידע רגיש שלא נחוץ לניהול סידור עבודה.

חתימות: _______________ (העסק)    _______________ (ShiftPilot)
```

## 3. איסוף נתונים לפני ההשקה

**המצב האמיתי במוצר** (לא תהליך ייבוא CSV — זה לא קיים): הגדרה ידנית דרך הממשק + הזמנות מייל אישיות לכל עובד. הכי מינימלי שאפשר:

- [ ] סניף אחד (אם עוד לא קיים בעסק).
- [ ] סוגי משמרות אמיתיים (לא "פתיחה/אמצע/סגירה" גנרי — השעות והתקנים האמיתיים של הסניף הזה).
- [ ] רשימת עובדים: שם + מייל + תפקיד (owner/manager/employee) בלבד — לא יותר מהמינימום.
- [ ] בדיקה משותפת עם ה-Sponsor: כל עובד ברשימה עם התפקיד הנכון, לפני שליחת ההזמנות.

## 4. Onboarding והשקה

תואם ל-5 הצעדים שכבר מוצגים בעמוד הבית (`app/page.tsx`), לא תהליך נפרד:

- [ ] **מפגש מנהל** (20–30 דקות): יצירת עסק/סניף, סוגי משמרות, פתיחת חודש עבודה ראשון.
- [ ] **דף עובד קצר** (לא מדריך ארוך) — מסך אחד: "איך מגישים זמינות, איך רואים משמרת, איך מבקשים החלפה". מבוסס על מרכז העזרה הקיים (`/workspace/help`), לא מומצא מחדש.
- [ ] **קבוצה קטנה קודם** — 2–3 עובדים ביום הראשון, לוודא שההזמנה/הכניסה/ההגשה עובדים בלי תקלות, ורק אז שולחים לכולם.
- [ ] **קריטריון סגירה:** המנהל והעובד משלימים את המשימה שלהם (הגשת זמינות / בניית סידור) בלי עזרה — לא רק "קיבלו הסבר".

## 5. מדידה ומשוב לאורך הפיילוט

**קו בסיס — לתעד *לפני* ההשקה, לא אחריה:**
- כמה זמן לוקח היום להכין סידור לחודש (הערכה של המנהל, גם אם לא מדויקת).
- כמה הודעות וואטסאפ/שיחות טלפון בערך עוברות סביב סידור והחלפות בחודש רגיל.

**באמצע ובסוף התקופה — פגישה קצרה, לא סקר ארוך:**
- מה עבד.
- מה לא עבד.
- האם הזמן/ההודעות ירדו בפועל (מול קו הבסיס).

**טריאז' בקשות — כדי שלא כל בקשה תהפוך לפיצ'ר (הסיכון המרכזי שהתוכנית מזהה):**

| קטגוריה | משמעות | טיפול |
|---|---|---|
| **Bug** | המוצר לא עושה מה שהוא אמור לעשות | תיקון מיידי |
| **Must** | חוסם את הפיילוט הזה ספציפית מלהצליח | לשקול לפני סוף הפיילוט |
| **Nice** | היה טוב שיהיה, לא חוסם | רשימת המתנה, לא עכשיו |
| **Custom** | ספציפי לעסק הזה, לא רלוונטי למוצר הכללי | לא נכנס למוצר — לדון בפתרון נקודתי אם בכלל |

## 6. סוף הפיילוט — Outcome Memo

```
פיילוט [שם העסק] — סיכום

תקופה בפועל: [תאריכים]
קו בסיס → תוצאה:
- זמן הכנת סידור: [X] → [Y]
- הודעות/שיחות סביב סידור: [X] → [Y]
- שביעות רצון מנהל (1-5): [ ]
- תקלות אמיתיות שנתקלו בהן: [רשימה, גם אם קצרה]

בקשות שסווגו:
- Bug: [כמות, תוקנו: כן/לא]
- Must: [כמות]
- Nice/Custom: [כמות — לא לטפל עכשיו]

החלטה: [ עצירה | הארכה | מעבר ללקוח משלם ]
נימוק: [משפט אחד, מבוסס על הנתונים למעלה — לא תחושת בטן]
```

## מה עדיין חסר כדי להריץ פיילוט אמיתי היום

- [ ] Sponsor מזוהה וקו בסיס מתועד אצל המועמד הנבחר (הולמס פלייס, לפי מה שכבר סוכם).
- [ ] Charter חתום בפועל — התבנית קיימת, החתימה לא.
- [ ] תרגום ה"דף עובד קצר" מ-`/workspace/help` הקיים למסך הדרכה חד-עמודי — לא בוצע כאן, זו עבודת תוכן קצרה בנפרד.
